# Deploying First Five on Render

## What gets created (`render.yaml`)

| Resource | Plan | Notes |
|---|---|---|
| `first-five` web service (Node) | **Free** | Serves the React app and the API. `healthCheckPath: /healthz` |
| `first-five-db` PostgreSQL 16 | **Free** | Internal connections only (`ipAllowList: []`) |

Region: Singapore (closest to India). Change both entries together if you prefer another region.

### Free-plan limitations (read before a live demo)
- **Cold starts:** a free web service sleeps after 15 minutes without traffic; the first request then takes ~1 minute. Open the site a few minutes before judging.
- **Ephemeral filesystem:** nothing is stored on local disk; all state is in PostgreSQL.
- **Database expiry:** free Render PostgreSQL databases expire **30 days after creation** (14-day grace to upgrade, then deleted). One free database per workspace. 1 GB storage.
- **No pre-deploy command** on free instances, so migrations run in the start command (`prisma migrate deploy && node …`).
- **Background work:** the in-process scheduler doesn't run while the instance sleeps. Correctness doesn't depend on it — deadlines are reconciled on demand on every relevant read — but PostHog delivery and retention purges pause. For always-on processing, add a paid Cron Job running `npm run admin:sweep`.

Upgrading either resource to a paid plan incurs charges; do that only deliberately.

## Build and start

```
build: npm ci --include=dev && npm run build     # prisma generate → vite build → tsup
start: npm start                                  # prisma migrate deploy && node apps/server/dist/index.js
```
- Node version: `.node-version` (22).
- The server binds `0.0.0.0:$PORT` and uses `RENDER_EXTERNAL_URL` as `APP_URL` automatically.
- Graceful shutdown on `SIGTERM` (closes HTTP, disconnects Prisma).
- `/healthz` = process health; `/readyz` = database reachable.

## Environment variables

| Key | Source |
|---|---|
| `DATABASE_URL` | From the database (Blueprint) |
| `SESSION_SECRET` | Generated by Render (Blueprint) |
| `NODE_ENV` | `production` |
| `SDK_SCRIPT_URL` | Add when the separately built SDK is hosted |
| `POSTHOG_*`, `AGENTICORG_*`, `PINELABS_*`, `PLUS_PRICE_MINOR` | Add only when connecting each integration |

Never commit secrets. Set them in **Dashboard → first-five → Environment**.

## Deploy steps

Render deploys Blueprints from a Git repository.

1. Push this repository to GitHub (private is fine; install the Render GitHub app for that repo).
2. Render Dashboard → **New → Blueprint** → select the repo → review the two free resources → **Apply**.
3. Wait for the first deploy, then open `https://<service>.onrender.com/readyz` — it should return `{"status":"ready","database":"ok"}`.
4. Create your account on the site, then make yourself an admin from **Shell** in the Render dashboard:
   ```bash
   npm run admin:grant-admin -- --email you@example.com
   ```
5. Generate judge codes (or use **/app/admin → Invitation codes**):
   ```bash
   npm run admin:codes -- --label "Judges" --audience judge --plan complimentary --count 10 --uses 1 --expires-days 30
   ```

### Using the Render API key locally
If you prefer the API/CLI, keep the key in your shell, never in files or chat:
```bash
export RENDER_API_KEY=…   # in your terminal only
```

## Smoke test after deploy
Read-only (creates no accounts, so production activity numbers stay genuine):
```bash
bash scripts/smoke.sh https://<service>.onrender.com
```
Then manually check: landing page, sample report, signup, create website (snippet shows **Setup preview** until `SDK_SCRIPT_URL` is set), status **Waiting for connection**.
